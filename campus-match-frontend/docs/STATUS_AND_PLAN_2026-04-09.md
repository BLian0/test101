# 校园匹配项目当前状态与后续计划

更新日期：2026-04-09

## 已完成部分

### 用户端前端
- 登录页：未登录访问任意用户页会自动跳回登录页。
- 登录方式：已改为“用户名 / 校园邮箱 + 密码”登录。
- 注册页：已收口为“用户名 + 校园邮箱 + 邮箱验证码 + 密码 + 确认密码”。
- 找回密码页：已支持校园邮箱验证码重置密码，重置成功后自动带回登录页。
- Onboarding：基础资料、问卷、偏好页面均可继续流转。
- 发现页、详情页、消息页、聊天页、我的页：页面主流程已可运行。
- 实时消息：前端已接入实时更新逻辑，收到消息后消息列表和聊天页会自动刷新。

### 管理后台前端
- 管理员登录。
- 用户列表。
- 举报列表与处理。
- 邮箱规则管理。
- 操作日志查看。

### 后端能力
- Auth、School、User、Questionnaire、Preference、Match、Chat、Block、Report、Admin 模块已搭起并可运行。
- 注册、登录、找回密码、资料、问卷、偏好、推荐、连接、聊天、举报、拉黑接口已存在。
- 校园邮箱验证码已接入 QQ SMTP 真实发送。
- 邮箱验证码已支持 5 分钟有效期，注册失败不会立即作废。
- 用户名已成为正式字段：
  - 注册时检查唯一性。
  - 仅允许英文字母、数字、下划线。
  - 不允许空格、非 ASCII 字母和其他符号。
  - 用户名与邮箱都可用于登录。
- 注册链路已去掉手机号和手机验证码依赖。
- 聊天已具备真实双用户主链路。
- 实时消息网关已接入，双方互发消息可自动刷新。

### 数据层与工程设施
- MySQL 已接通并可作为主要存储运行。
- SQLite / MySQL 双存储实现已存在。
- 已支持真实鉴权用户上下文，不再固定为单一演示用户。
- 推荐池已从纯硬编码候选人切到真实注册用户主链路。
- 已提供桌面一键启动脚本。
- 已保留版本快照：`v1.0407beta`。

## 当前已跑通的真实主链路
- 用户 A、用户 B 可分别注册。
- 用户 A 可以登录并看到推荐用户。
- 用户 A 可以对用户 B 建立连接。
- 用户 B 登录后可以看到该连接。
- 用户 A 可以发送首条消息。
- 用户 B 可以收到并回复。
- 用户 A 可以自动看到回复，无需手动刷新聊天页。
- 用户可以进行举报、拉黑、取消拉黑。
- 管理后台可以查看用户、举报、日志。

## 当前未完成部分

### 账号与安全
- 密码仍为明文存储，尚未切到安全哈希。
- 验证码尚未迁移到 Redis 缓存层，但当前先不做。
- 邮箱验证码发送频率限制、防刷、图形验证码还未做。
- 登录态与权限体系仍偏 MVP，缺少更完整的风控约束。
- 后端废弃手机号接口和前端残留仍需继续清理。

### 聊天与消息
- 未读数、已读状态、在线状态仍较粗糙。
- 图片 / 语音消息链路还需要继续补强和回归。
- 会话搜索、筛选、排序能力未完善。

### 推荐与匹配
- 推荐逻辑仍是 MVP 级，不是最终版本。
- 问卷结果驱动的匹配算法还需要继续细化。
- “不感兴趣”“跳过后回流策略”等还需补完整。

### 管理后台
- 搜索与筛选能力不完整。
- 举报处理维度还不够细。
- 封禁、解封、审核备注等还可以继续完善。

### 前端体验
- 页面视觉风格还没有彻底收敛到最终版。
- 还有部分状态页、空状态、异常状态需要精修。
- 双账号、多浏览器场景仍需要系统性人工回归。

### 工程与数据结构
- 部分历史开发态逻辑和临时实现仍需清理。
- 数据表结构还可以继续规整。
- 需要逐步提升测试覆盖率。

## 接下来的执行计划

### 第一阶段：安全和账号体系收口
1. 将密码存储切换为安全哈希。
2. 清理废弃手机号接口、错误码和前端残留。
3. 增加邮箱验证码发送频率限制和基础防刷。

### 第二阶段：真实多用户回归
1. 用两个真实账号完整跑通注册、登录、找回密码、连接、聊天、举报、拉黑。
2. 修复多账号场景下的状态同步问题。
3. 补齐空状态、错误状态和加载状态。

### 第三阶段：聊天体验升级
1. 完善未读数和会话状态。
2. 继续补图片 / 语音消息体验。
3. 优化聊天列表和详情页的实时更新表现。

### 第四阶段：推荐与匹配升级
1. 继续细化问卷标签和匹配策略。
2. 优化推荐池筛选与排序。
3. 完善跳过、不感兴趣、拉黑后的回流逻辑。

### 第五阶段：管理后台增强
1. 增加搜索与筛选。
2. 增加更细的举报处理流程。
3. 完善封禁、解封和日志追踪能力。

### 第六阶段：前端统一收尾
1. 对登录、注册、发现、详情、消息、聊天、我的页做最后一轮统一打磨。
2. 修掉残余文案、状态和视觉不一致问题。
3. 为后续上线和内测准备更稳定的产品状态。
