# 校园搭子后端模块拆分 v0.1

## 1. 后端总览

第一版后端建议采用 `NestJS 单体模块化` 架构。

原因：

- 功能模块多，但团队规模小
- 比微服务更容易启动和维护
- 便于后期按模块拆分

## 2. 模块划分

### `auth`

职责：

- 注册
- 登录
- Token 签发
- 手机验证码
- 邮箱验证码
- 账号绑定规则

### `school`

职责：

- 学校数据
- 邮箱后缀规则管理
- 学校配置查询

### `user`

职责：

- 用户主体
- 基础资料
- 头像上传
- 资料完成度计算

### `questionnaire`

职责：

- 问卷版本管理
- 题目管理
- 选项管理
- 提交问卷
- 计算标签和维度分

### `preference`

职责：

- 理想对象偏好存储
- 偏好读取

### `match`

职责：

- 推荐候选生成
- 匹配分计算
- 刷人行为记录
- 匹配原因解释
- 建立连接

### `chat`

职责：

- 首条私信
- 双向聊天权限
- 文本消息
- 图片消息
- 语音消息
- 联系方式敏感词拦截

### `block`

职责：

- 拉黑
- 黑名单查询
- 拉黑联动推荐和聊天

### `report`

职责：

- 举报提交
- 举报证据
- 举报状态流转

### `upload`

职责：

- 头像上传
- 图片上传
- 语音上传

### `admin`

职责：

- 管理员登录
- 用户管理
- 举报处理
- 学校邮箱规则管理
- 问卷版本管理

### `common`

职责：

- 全局异常
- 响应封装
- 审计日志
- 枚举常量
- 工具函数

## 3. 推荐调用链

推荐流程建议：

1. 用户完成问卷
2. `questionnaire` 计算标签和 traits
3. `preference` 读取理想对象偏好
4. `match` 生成候选池
5. `match` 输出匹配分和解释摘要

## 4. 聊天调用链

聊天流程建议：

1. `match` 或连接逻辑创建 `user_connections`
2. `chat` 判断连接状态
3. 首条私信进入敏感词校验
4. 对方回复后升级连接状态
5. 后续正常写入消息

## 5. 技术边界

### 第一版同步处理

建议同步处理：

- 注册校验
- 基础资料更新
- 首条私信校验

### 第一版异步处理

建议异步处理：

- 问卷分数计算
- 匹配候选池刷新
- 举报通知
- 媒体文件转码/处理
