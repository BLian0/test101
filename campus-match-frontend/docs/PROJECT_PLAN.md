# 校园搭子项目计划

## 1. 项目目标

本项目第一阶段目标是做一个面向本校大学生的 H5 内测产品，定位为 `校园搭子`，但匹配核心是 `恋爱兼容度匹配`。

第一版不追求复杂推荐算法上线，而是优先验证：

- 用户是否愿意注册并认证
- 用户是否愿意做匹配测试
- 用户是否愿意刷人
- 建立连接后是否愿意开始聊天
- 产品是否有形成日活的潜力

当前第一目标指标：

- 日活

## 2. 当前明确不做的事情

以下内容不进入第一版开发范围：

- 邀约广场正式功能
- 付费会员
- 运营位
- 视频通话
- 多学校联动
- 复杂机器学习推荐

说明：

- 邀约页保留入口，但只显示“稍后上线”
- 推荐分算法第一版以规则和问卷分数为主

## 3. 第一版必须做的事情

### 用户体系

- 校园邮箱注册
- 校园邮箱登录
- 手机号登录
- 校园邮箱规则校验
- 同校用户限定
- 注册时同时验证手机号验证码和校园邮箱验证码

### 基础资料

- 昵称
- 头像
- 年龄
- 性别
- 性取向
- 自我介绍（可选）

### 匹配体系

- 刷人推荐流
- 匹配测试问卷
- 理想对象偏好问卷
- 标签结果生成
- 维度分结果结构预留
- 高匹配用户优先展示
- 拉黑

### 聊天

- 建立连接后允许发送 1 条首条私信
- 对方回复后开放双向聊天
- 文字消息
- 图片消息
- 语音消息
- 开放双向聊天后允许交换联系方式

### 安全风控

- 举报入口
- 人工处理举报
- 拉黑后互相不可见
- 举报类型管理
- 首条私信阶段联系方式拦截

### 管理后台

- 用户管理
- 举报处理
- 拉黑/封禁
- 校园邮箱规则管理
- 问卷题目与版本配置预留

## 5. 建议技术路线

### 前端

- uni-app
- Vue 3
- TypeScript
- Pinia

### 后端

- NestJS
- MySQL
- Redis
- 对象存储

### 后台

- Vue 3
- Element Plus

### 匹配

第一版建议按以下结构实现：

1. 问卷原始答案
2. 标签结果
3. 维度分数
4. 匹配规则计算

### 聊天

第一版建议按以下顺序实现：

1. 文字消息
2. 图片消息
3. 语音消息
